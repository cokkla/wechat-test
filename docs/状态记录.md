## 2026-09-17

### 完成 - 游标持久化（修复重复回复问题）
- **问题**：每次重启服务后，`_cursor_store` 被清空，导致 `sync_msg` 从头拉取所有历史消息（包括已回复过的），然后每条 `origin == 3` 的消息都触发回复，很快触发微信客服 **95001: send msg count limit** 错误（48小时内最多回复5条）。
- **解决方案**：将游标持久化到 `cursors.json` 文件：
  - `_load_cursors()`: 启动时从文件加载已保存的游标位置。
  - `_save_cursors()`: 每次 `sync_msg` 更新游标后立即保存到文件。
  - 在 `if __name__ == "__main__"` 入口调用 `_load_cursors()`。
- 更新 `.gitignore` 新增 `cursors.json`（游标文件不提交到版本库）。
- 补充 `test_server.py` 测试用例（新增 4 个，总计 27 个全部通过）：
  - `TestSyncMsg.test_saves_cursor_after_each_page`: 验证每次分页后都调用 `_save_cursors()`。
  - `TestCursorPersistence`: 验证加载、保存游标文件，以及缺失文件时的容错逻辑。

### 待验证（需用户在真实环境测试）
- 重启服务后，客户发送新消息时不会再触发历史消息的重复回复。（✅ 验证通过）
- `cursors.json` 文件能否正确生成并在下次启动时加载。（✅ 验证通过）

## 2026-09-17（中期）

### 完成 - 文件接收功能
- 实现 `download_media()` 函数：调用企业微信 `GET /cgi-bin/media/get` 接口下载临时素材（图片/语音/视频/文件），保存到 `downloads/` 目录。
  - 自动从响应头 `Content-Disposition` 提取文件名，若无则用 `media_id` 前 16 位生成。
  - 文件名追加时间戳（毫秒）避免冲突。
  - 判断响应类型：`application/json` 表示 API 错误，其他为二进制流。
  - 返回 `{"success": bool, "filepath": str, "filename": str, "size": int, "error": str}`。
- 修改 `_handle_kf_event()` 消息处理逻辑：
  - 识别 `msgtype in ["image", "video", "voice", "file"]` 的消息，提取 `media_id` 并调用 `download_media()`。
  - 下载成功后回复：`"已成功接收{文件名}文件，大小{size_mb:.2f}MB"`。
  - 下载失败回复：`"文件接收失败：{error}"`。
  - 文本等非文件消息仍回复固定文本"成功接收消息"。
- 更新 `.gitignore` 新增 `downloads/` 目录（避免提交用户文件）。
- 补充 `test_server.py` 测试用例（新增 7 个，总计 23 个全部通过）：
